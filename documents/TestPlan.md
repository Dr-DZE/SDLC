## 1. Введение

### 1.1 Назначение документа
Документ описывает стратегию и подход к тестированию веб-приложения **To-Do List**, предназначенного для управления задачами и проектами. Цель тестирования — подтвердить соответствие системы требованиям, изложенным в SRS, а также обеспечить стабильность и корректность работы основных функций.

### 1.2 Объекты тестирования
- **Клиентская часть:** Thymeleaf, HTML, CSS, JS
- **Серверная часть:** Spring Boot, Java
- **База данных:** H2 Database
- **Безопасность:** Spring Security (аутентификация, авторизация, хеширование паролей)

### 1.3 Ссылки
- `SRS.pdf`
- `component_diagram.puml`

## 2. Цели тестирования
- Проверить корректность ключевых функций (регистрация, вход, CRUD задач и проектов).
- Убедиться, что фильтрация и сортировка задач работают согласно требованиям.
- Проверить валидацию данных на бэкенде (например, обязательные поля).
- Подтвердить целостность данных в H2 (связи между задачами и проектами).
- Оценить устойчивость к ошибкам пользователя и корректность их обработки.
- Проверить базовую безопасность (доступ к данным только для аутентифицированных пользователей).

## 3. Область тестирования

### 3.1 Включено
✅ Регистрация / авторизация / выход
✅ CRUD операций для Задач
✅ CRUD операций для Проектов
✅ Привязка задач к проектам
✅ Фильтрация задач по сложности
✅ Отображение ошибок валидации
✅ Проверка сохранения данных в H2

### 3.2 Не включено (MVP)
❌ Расширенный режим "суперзаданий" (`new_page.html`)
❌ Масштабное нагрузочное и стресс-тестирование
❌ Тестирование на мобильных устройствах
❌ Локализация и поддержка нескольких языков

## 4. Стратегия тестирования

| Тип | Детали |
|---|---|
| **Модульные тесты (Unit)** | Логика сервисов и контроллеров (JUnit, Mockito) |
| **Интеграционные тесты** | Взаимодействие API с базой данных (Spring Boot Test) |
| **Функциональные UI-тесты** | Ручная проверка ключевых сценариев пользователя в браузере |
| **Smoke-тесты** | Быстрая проверка работоспособности после сборки (запуск, открытие главной страницы) |
| **Регрессионные тесты** | Повторное выполнение ключевых тестов после исправления багов или добавления новой функции |

## 5. Виды тестирования

### 5.1 Функциональные
- Регистрация, вход, выход
- Создание / редактирование / удаление задач
- Создание / редактирование / удаление проектов
- Фильтрация задач
- Проверка корректности отображения всех элементов UI

### 5.2 Нефункциональные

| Вид | Цель |
|---|---|
| **Производительность** | Время отклика сервера на ключевые запросы < 2 сек (согласно SRS) |
| **Безопасность** | Проверка хеширования паролей (BCrypt), защита эндпоинтов через Spring Security |
| **UX/UI** | Корректное отображение на desktop-браузерах (Chrome), интуитивность интерфейса |
| **Надёжность** | Проверка поведения системы при некорректном вводе данных |

## 10. Оценка рисков

| Риск | Вероятность | Влияние | Митигирование |
|---|---|---|---|
| Повреждение файла БД (H2) | Низкая | Среднее | Регулярные бэкапы, использование версионных миграций (Flyway/Liquibase) |
| Ошибка в конфигурации Spring Security | Средняя | Высокое | Code review, следование официальной документации, использование стандартных практик |
| Некорректное отображение UI | Средняя | Низкое | Ручное тестирование на целевых разрешениях экрана |
